## Context

Bean Blog 当前以 `src/posts/**/*.md`、`PostData` 和 `/blog` 动态路由服务中文长文。全局 `Layout.vue` 统一提供站点 Header、Footer 和明暗模式，主题以 Tailwind CSS 4 utility 与 `tailwind.css` 语义令牌实现，并已有可复用的照片预览、分页、base path 和构建期草稿过滤能力。

Icefox 的辨识度主要来自朋友圈式信息结构：大幅个人封面、右下方重叠头像与昵称、窄幅单列动态、左头像右正文、图片宫格、时间地点和紧凑操作区。它的 Typecho/PHP 数据访问、登录、点赞、评论和样式实现不适合直接进入完全静态的 VitePress 工程。本变更只借鉴这些结构和交互关系，具体视觉必须服从 Bean Blog 现有字体、颜色、尺寸、导航和组件边界。

短动态与长文章属于不同内容类型。作者会在独立目录中维护简短 Markdown，而不是让现有手册或后续长文兼容朋友圈卡片。

## Goals / Non-Goals

**Goals:**

- 提供独立、经过构建期校验且支持草稿预览的短动态内容模型。
- 提供单一 `/moment` 页面，以 Icefox 式朋友圈结构和滚动分批加载展示短文本与一至九张图片。
- 使用 Moment 专用 Header，同时保持全站 Footer、字体、语义颜色、明暗模式、响应式断点、焦点样式和照片预览一致。
- 让每条动态具有稳定锚点与真实可用的复制链接操作。
- 复用现有加载、排序、分页、路径和媒体基础设施，不影响 `/blog` 的文章集合及其发现能力。

**Non-Goals:**

- 不把现有长文章转换为动态，也不在 `/moment` 中展示 `src/posts` 内容。
- 不新增动态详情路由、动态标签页、动态搜索或独立 feed。
- 不提供需要服务端状态的全站点赞、信息流内逐条评论、登录、发布后台或无构建即时发布。
- 不承诺在动态正文中支持 Vue 组件、Live Photo、代码组、数学公式或长文章完整排版；首版正文面向普通短 Markdown。
- 不逐像素复刻 Icefox，不复制其 PHP、CSS、品牌素材或未经明确授权的资源。

## Decisions

### 1. 独立内容类型共享基础管线

新增 `src/moments/**/*.md`、`MomentFrontmatter` 和 `MomentData`。动态与文章分别保持清晰契约，但日期解析、slug 规范化、草稿过滤、排序、分页和 base path 等无业务差异的逻辑下沉为共享工具；不得复制出第二套等价算法。

动态 frontmatter 使用以下核心字段：

- `date`：必填的有效日期或日期时间。
- `title`、`updated`、`location`：可选非空字符串，其中 `title` 仅用于内部描述和辅助语义，不在普通动态卡片中作为文章标题展示。
- `tags`：默认空数组，成员规范化并去重。
- `images`：构建期归一化后的图库数组，每项包含非空 `src` 和 `alt`，最多九项；优先从正文末尾图片 token 提取，迁移期也接受旧 frontmatter 字段。
- `pinned`、`draft`：默认 `false`。

站点是单作者博客，动态作者名、头像、个人封面列表和签名来自 `site.config.ts` 的集中 `moment` 配置，不为每条动态重复声明。配置未单独提供显示名、头像或签名时回退到现有站点作者与 favicon；封面列表至少包含一个非空的本地公开资源，并在规范化后去重。

备选方案是复用 `PostData` 并增加 `kind` 字段。该方案会让长文必填标题、SEO、系列、字数和阅读时间污染短动态契约，也容易让文章搜索、标签、归档和 feed 意外混入动态，因此不采用。另一备选方案是为 moments 复制完整 loader；这会产生两套草稿和排序规则，也不采用。

### 2. 从正文末尾的 Markdown token 提取图库

作者优先在简短正文之后使用标准 `![替代文本](公开路径)` 语法声明图片。图片必须连续位于正文末尾，可占据一个或多个纯图片段落；每项必须提供非空路径和非空 `alt`，总数最多九张。链接图片、图片 title、图文混排段落、分散的多段图库或图片之后继续出现正文都会在构建期失败。

VitePress 配置的 Markdown renderer 在构建期生成可信 HTML。Moment core rule 直接检查 parser token，将合法的尾部图片 token 转为 `MomentImage[]`，并连同其段落容器从正文 token 流移除；提取结果暂存在本次解析的 Markdown env，数据 loader 使用相同 token 规则取得图库元数据，再交给既有 schema 和 `MomentGallery`。元数据不能依赖模块内存注册表，因为 VitePress 配置与 `.data.ts` 会分别打包插件模块但共享 renderer 单例。浏览器不解析 Markdown，系统也不使用正则、最终 HTML 提取或整篇字符串替换。

迁移期继续接受旧 frontmatter `images: [{ src, alt }]`，但单条动态不能同时使用 frontmatter 图片和正文图片。这样现有内容无需一次性迁移，新内容则拥有更自然的 Markdown 写作体验；迁移完成后可由后续 change 移除旧字段入口。

备选方案是像 Icefox 一样从最终 HTML 提取图片。该方案依赖脆弱的字符串处理，违反项目 Markdown 扩展约束，也无法稳定保留 `alt`，因此不采用。把图片继续只放在 frontmatter 会让短动态的主要内容被拆到两个区域，不利于持续写作，因此改为迁移兼容项。直接允许正文 Vue 组件则无法通过聚合页的静态 HTML 自动挂载组件，也不采用。

### 3. 聚合路由采用客户端分批揭示和稳定锚点

`src/moment/index.md` 是唯一公开动态路由。构建期仍一次生成经过校验、过滤和排序的完整 `MomentData` 集合；浏览器首屏只渲染 `momentBatchSize` 条，使用 `IntersectionObserver` 观察列表底部哨兵并按批追加，不发起分页请求，也不在运行时解析 Markdown。哨兵同时提供可聚焦的“加载更多动态”按钮作为键盘与不支持观察器环境的回退，并在末尾显示明确完成状态。

每条动态从完整嵌套 slug 派生唯一 DOM id，复制链接统一指向 `/moment#fragment`。直接打开深链时，页面先计算目标在已排序集合中的位置、扩大可见批次，再在 DOM 更新后定位目标，因此较后的动态无需分页 URL 也可稳定访问。`/blog` 的分页实现保持不变。

备选方案是首屏一次渲染全部动态，会让图片数量增长后拖慢首屏。继续生成静态分页则割裂社交信息流，也与明确的滚动浏览预期冲突。这里采用静态全集加客户端渐进揭示，在不引入 API、请求失败与列表合并状态的前提下获得 Icefox 式连续浏览体验。

### 4. Icefox 提供结构，Bean Blog 提供视觉语言

`Layout.vue` 在 `layout: moment` 时不渲染全局 `SiteHeader`，改由 52px 高的 Moment 专用 Header 覆盖个人封面顶部：左侧使用返回首页命令，右侧复用现有 `ThemeSwitcher`，滚动离开封面后显示“动态”标题并切换为半透明语义背景与磨砂模糊。Header 自身宽度 SHALL 与 `max-w-content` 中央内容一致，不以贯穿 viewport 的边框分隔。动态页不承载文章搜索或完整全站导航，`SiteFooter` 仍复用现有实现。页面外层使用 `muted`，中央封面与信息流使用 `background`，形成类似 Hugo-Theme-Amigo 的画布与内容面层关系；两者在暗色模式下仍使用各自同名语义令牌。顶部个人区在每次组件挂载时从配置列表随机选择一张真实封面，并显示右下方昵称、越过封面下沿的方形头像和封面下方右对齐签名。服务端初始输出使用列表第一张，客户端挂载后再确定本次随机封面，避免 hydration 不一致；停留期间封面保持稳定。

动态列表不使用浮动卡片背景或层层容器，而以细分隔线组织。每项使用稳定的头像列和弹性正文列：作者名使用 `primary`，正文使用 `foreground`，日期、地点和标签使用现有 muted/primary 语义角色。字体继续使用 LXGW WenKai Lite，圆角不超过现有设计尺度，所有颜色来自 `oklab()` 语义令牌。宽屏保持安静、窄幅的信息流，移动端利用完整可用宽度但保持页面 gutter。

专用 Header 借鉴 Icefox 的透明到实色滚动状态和 Amigo 的返回、主题操作关系，但控件尺寸、焦点和颜色继续来自 Bean Blog。若参考主题的具体样式与现有设计系统冲突，以现有设计令牌、组件交互和可访问性规则为准。

### 5. 卡片行为保持紧凑且可访问

正文默认限制为六行。组件挂载和内容更新后比较实际高度，仅在发生溢出时显示“全文”；按钮使用 `aria-expanded` 和稳定的内容关联，展开后提供“收起”，不通过内联 style 控制状态。没有正文但有图片的动态仍可正常展示。

图库规则为：单图在限定最大宽高内保留固有比例；二图和四图使用两列；三图及五至九图使用三列等大方形缩略图。所有图片声明固定比例或尺寸，避免加载时推动布局，并复用现有 `data-photo-preview`、键盘入口和 `PhotoPreview` dialog；图片 URL 必须经过 `withBase`。

底部日期参考 Hugo-Theme-Amigo 的朋友圈规则：当天显示 `HH:mm`，昨天显示“昨天”，过去七个日历日内显示中文星期，今年更早显示“月日”，跨年显示“年月日”；`time` 元素仍保留标准 `datetime`，并通过完整时间提示提供精确信息。底部还显示可选地点与标签，以及 Lucide `Ellipsis` 操作按钮。弹出菜单首版只提供“复制链接”，复制成功必须有非仅颜色的状态反馈；Clipboard API 不可用时使用兼容回退。按钮、popover、展开控件和图片均支持键盘操作、可见焦点和合适的无障碍名称。

备选方案是展示无后端的点赞数量或在每张卡片嵌入 Giscus。前者会制造虚假全局状态，后者会产生大量 iframe 且 pathname 映射不能自然区分聚合页中的条目，因此均不采用。

### 6. 发现范围与现有文章能力隔离

只有 `/moment` 页面由 VitePress 进入 sitemap；动态条目本身以页面内 fragment 分享，不产生单独 sitemap item，也不生成 `/moment/page/*`。现有文章搜索、文章标签、文章归档、系列 sidebar 和 RSS/Atom/JSON Feed 继续只消费 `src/posts`，不得因为新增 moments loader 改变结果。

站点主导航增加“动态”入口。动态标签首版仅作为卡片元数据展示，不链接到现有文章标签页，以免产生错误的混合集合。使用手册新增动态写作章节，说明目录、字段、图片资源、草稿、置顶、分页和首版互动边界。

## Risks / Trade-offs

- [聚合页通过静态 HTML 展示 Markdown，无法挂载正文中的 Vue 组件] → 明确限定首版正文语法，尾部图片由构建期 token 转成结构化数据并交给 Vue 图库组件处理。
- [提取图库需要在 content loader 中再次解析短动态原文] → 第二次解析只读取构建期 token 元数据，不渲染或处理客户端内容；正式正文 HTML 仍由项目统一配置的 VitePress renderer 生成。
- [置顶动态会长期占据每一轮构建后的第一页] → 置顶状态显式配置并在手册说明，测试确保只有作者标记的条目提前。
- [嵌套 slug 转换为 fragment 时可能冲突] → 使用单一编码函数生成 DOM id，并在构建期校验完整 slug 与最终 fragment 均唯一。
- [封面和多图增加移动端下载量] → 图片使用原生懒加载、固定尺寸和分批渲染；首屏个人封面允许优先加载，其余动态图片保持 lazy。
- [客户端随机封面可能造成 hydration 不一致或停留期间跳变] → 服务端固定输出首张，组件挂载后只随机一次，并在当前页面生命周期内保持结果。
- [Moment 专用 Header 可能与既有博客看起来像两个产品] → 复用现有 `ThemeSwitcher`、字体、语义令牌、容器、控件、焦点、暗色模式和 Footer，并通过桌面与移动截图回归检查连续性。
- [深链目标初始未渲染导致浏览器无法定位] → 挂载时先按目标索引扩大可见批次，再在 DOM 更新后显式滚动到稳定 fragment。
- [没有点赞和逐条评论会弱化社交感] → 首版把朋友圈感建立在信息层级与媒体编排上，只展示真实功能；后续若引入详情路由或 Artalk，再以独立 change 增加互动。
- [Icefox 本地仓库的许可文件与 README 声明不一致] → 只把它作为行为和构图参考，所有 Vue/Tailwind 代码与资产重新实现，不复制其源码或素材。

## Migration Plan

1. 先建立共享内容工具和 `MomentData` 校验，加入覆盖有效、无效、草稿、置顶、排序与 fragment 唯一性的单元测试。
2. 增加单一 `/moment` 路由、站点配置和导航入口，并用少量文档型示例动态验证生产过滤与静态产物。
3. 实现专用 Header、个人封面、滚动加载、深链揭示、朋友圈时间、动态卡片、文本展开、图库、照片预览和复制链接，完成桌面、移动、明暗模式与键盘回归。
4. 将图库写作入口迁移为正文末尾标准图片语法，保留旧 frontmatter 兼容层，并补充 token 提取、非法结构和混用失败测试。
5. 更新正式使用手册，运行格式、样式、lint、类型、单元测试和 OpenSpec strict validation；UI 在 dev 服务中验收，发布验证时再执行完整生产检查。
6. 回滚时移除导航和 `/moment` 页面即可恢复原公开界面；`src/moments` 内容与独立配置不会改变现有 `/blog` 数据或路由。

## Open Questions

无阻塞问题。正式个人封面和头像由站点身份配置提供；在身份尚未完成时，开发与测试使用仓库内明确标注的本地占位资源。
