## Context

Bean Blog 当前以 `src/posts/**/*.md`、构建期文章模型和 `/blog` 路由服务中文长文。全局布局统一提供 Header、Footer、明暗模式和基于 Tailwind CSS 4 语义令牌的视觉体系，也已有文章引用、音乐、视频、Live Photo、照片预览、base path 与草稿过滤等能力。

Moment 面向微博、X、Instagram 或朋友圈式短内容，作者会在独立目录中维护简短 Markdown，而不是让现有长文模型兼容另一套展示语义。页面借鉴 Icefox 的信息结构与 Hugo-Theme-Amigo 的时间表达，但所有实现、资源和颜色必须服从 Bean Blog 的模块边界和设计令牌。

动态需要在同一条正文中保持普通 Markdown 与多种富媒体的源顺序。该顺序在 Markdown parser token 阶段已经明确，因此最终模型应直接保存结构化内容块，不把信息降级为 HTML marker 后再由浏览器通过正则或 DOM 查询恢复。

## Goals / Non-Goals

**Goals:**

- 提供独立、经过构建期校验并支持开发环境草稿预览的短动态内容模型。
- 提供单一 `/moment` 页面，以朋友圈式结构和滚动分批加载展示短文本、普通图库和四种既有富媒体。
- 在构建期生成有序 `MomentContentBlock[]`，直接表达普通 HTML 与富媒体的类型和顺序。
- 使用 Moment 专用 Header，同时保持全站字体、语义颜色、明暗模式、响应式规则、Footer、媒体组件和照片预览一致。
- 让每条动态具有稳定锚点、当前动态内的图库翻页和真实可用的复制链接操作。

**Non-Goals:**

- 不把现有长文章转换为动态，也不在 `/moment` 中展示 `src/posts` 内容。
- 不新增动态详情路由、分页路由、动态搜索、独立 Feed、标签聚合或即时发布后台。
- 不提供需要服务端状态的全站点赞、信息流内逐条评论或登录能力。
- 不允许 Moment 使用所有长文章 Markdown 扩展；代码组、数学公式、`image-grid` 和任意 Vue 组件不在范围内。
- 不逐像素复刻 Icefox 或 Hugo-Theme-Amigo，不复制其源码、品牌素材或硬编码颜色。

## Decisions

### 1. 独立内容类型共享构建期基础设施

新增 `src/moments/**/*.md`、`MomentFrontmatter` 和 `MomentData`。动态与文章分别保持清晰契约，但日期解析、slug 规范化、草稿过滤、排序和 base path 等无业务差异的逻辑使用现有共享工具。

动态 frontmatter 以 `date` 为必填字段，`title`、`updated`、`location`、`tags`、`pinned` 和 `draft` 按需声明；`images` 仅作为迁移期兼容入口。站点是单作者博客，显示名、头像、签名、个人封面列表和每批数量集中配置在 `site.config.ts`，避免每条动态重复身份数据。

备选方案是复用 `PostData` 并增加 `kind`。这会让长文标题、SEO、系列、字数和阅读时间污染短动态契约，也容易使搜索、标签、归档和 Feed 意外混入动态，因此不采用。

### 2. parser token 直接形成最终有序内容块

Moment 数据加载器只读取原始 Markdown，并使用与 VitePress 一致的 renderer 完成一次 parse。普通 token 连续分段后渲染为 `{ type: "html", html }`；`link-card`、`music`、`video` 和 `live-photo` 插件在 Moment 环境中完成各自校验，把结构化媒体写入替换 token 的 metadata，并生成对应的可判别内容块。`MomentData.content` 按最终 token 顺序保存全部块，`MomentCard` 直接按 `type` 选择既有 Vue 组件。

非 Moment 来源继续由相同插件输出长文章所需的组件标签。可播放媒体是否禁用六行裁切直接由内容块类型推导；只有文本是否真实溢出仍通过浏览器布局测量。

备选方案是向最终 HTML 写入注释 marker，同时维护媒体数组，再在 Vue 运行时用正则拼回顺序并查询子组件 DOM 判断类型。它把同一份顺序拆成双轨协议，也会让新增媒体类型同时维护 marker、正则、DOM 属性和组件分支，因此不采用。普通 Markdown 的可信构建期 HTML仍使用 `v-html`，它不承担内容类型解析。

### 3. 正文末尾提取普通图库并隔离富媒体资源

作者在简短正文末尾使用标准 `![替代文本](公开路径)` 声明普通图库。Moment core rule 基于 parser token 识别一个或多个连续的纯图片段落，将图片按顺序写入图库并从正文 token 流移除。每项必须有非空路径和 `alt`，最多九张；链接图片、title、图文混排、分散图库、图片后的正文或富媒体，以及正文图片与 frontmatter `images` 混用均在构建期失败。

受支持富媒体容器可以位于普通正文之间或图库之前。扫描图库时显式排除四种容器的完整 token 范围，因此音乐和视频封面、Live Photo 静态首帧只归属对应组件，不计入普通图库。每种容器继续复用长文章已有的参数解析、地址限制、错误位置和组件，不建立 Moment 专用语法或重复校验。

备选方案是从最终 HTML 提取图片或把所有媒体写进 frontmatter。前者依赖脆弱的字符串处理且无法稳定保留语义，后者会把短动态内容拆到两个区域，因此不采用。

### 4. 单一聚合路由使用客户端渐进揭示和稳定锚点

`src/moment/index.md` 是唯一公开动态路由。构建期生成经过校验、过滤和排序的完整 `MomentData` 集合；浏览器首屏只渲染 `momentBatchSize` 条，通过 `IntersectionObserver` 观察底部哨兵并按批追加，不请求分页页面，也不在运行时解析 Markdown。哨兵提供可聚焦的手动加载按钮作为键盘和无观察器环境的回退。

每条动态从完整嵌套 slug 派生唯一 fragment，复制链接统一指向 `/moment#fragment`。直接打开较后的 fragment 时先扩大可见批次，再在 DOM 更新后定位目标。

备选方案是一次渲染全部动态或生成静态分页。前者会随媒体数量增长拖慢首屏，后者割裂连续信息流，因此采用静态全集加客户端渐进揭示。

### 5. Icefox 提供结构，Bean Blog 提供视觉语言

`Layout.vue` 在 `layout: moment` 时跳过通用 `SiteHeader`，改用 52px 高、宽度与中央内容一致的 Moment 专用 Header。Header 覆盖封面顶部，提供返回首页和现有主题切换；滚动后显示“动态”标题，并使用无硬边框的半透明语义背景与磨砂模糊。

页面外层使用现有 `muted` 面层，两侧画布与使用 `background` 的中央信息流形成对比；封面本身不保留圆角。个人区从配置列表随机选择一张本地公开路径或完整远程 URL，服务端先输出第一张，客户端挂载后只选择一次，以避免 hydration 不一致和停留期间跳变。动态列表使用左头像、右正文和细分隔线，不使用浮动白卡或额外硬编码色板。

备选方案是复用通用 Header 或复制参考主题颜色。前者会破坏朋友圈封面的构图，后者会使 Moment 与当前博客像两个产品，因此使用专用结构和既有设计令牌。

### 6. 交互保持紧凑、真实且可访问

纯文本正文默认限制为六行，只有布局测量确认溢出时才显示“全文/收起”。包含音乐、视频或 Live Photo 的内容不裁切，确保播放控件完整可用。

普通图库一图保留受限原比例，二图和四图使用两列，其余多图使用三列方形缩略图。图库复用全站 `PhotoPreview`，但每条 `MomentGallery` 建立独立预览 scope，使左右翻页只遍历当前动态的图片；预览导航与图片禁止文本选择，避免拖动或连续点击产生系统蓝色高亮。

日期参考朋友圈规则：当天显示 `HH:mm`，昨天显示“昨天”，过去七个日历日内显示中文星期，今年更早显示“月日”，跨年显示“年月日”；`time` 仍保留标准 `datetime` 与精确时间提示。操作菜单只提供真实可用的“复制链接”，并覆盖 Clipboard API 回退、状态反馈、Escape、外部点击和焦点恢复。

备选方案是在每张卡片显示无后端的点赞数量或嵌入评论 iframe。前者制造虚假状态，后者会引入大量实例且无法自然映射聚合页条目，因此均不采用。

### 7. 动态发现范围与文章能力隔离

只有 `/moment` 页面进入 sitemap；fragment 不作为独立条目，也不生成 `/moment/page/*`。现有文章搜索、标签、归档、系列 sidebar、RSS、Atom 和 JSON Feed 继续只消费 `src/posts`。主导航增加“动态”入口，动态标签首版只作为卡片元数据显示。

## Risks / Trade-offs

- [聚合页包含较多媒体时客户端负载增长] → 构建期只生成一份静态数据，页面按批渲染，普通图片懒加载并声明稳定尺寸。
- [分段渲染可能改变普通 Markdown 与富媒体之间的空白] → 只在顶层富媒体 token 处分段，连续普通 token 交给同一个 renderer，并用混排测试固定结果。
- [容器插件需要区分长文章与 Moment 输出] → 差异集中在统一的 token metadata helper，参数解析和校验保持共用。
- [远程封面、音频或视频可能失效] → 沿用浏览器和既有媒体组件的错误状态；静态正文与其他动态不受影响。
- [嵌套 slug 派生 fragment 时可能冲突] → 构建期同时校验完整 slug 和最终 fragment 唯一性。
- [客户端随机封面可能造成 hydration 不一致] → SSR 固定使用首张，挂载后只随机一次并在当前页面生命周期内保持稳定。
- [深链目标尚未进入首批 DOM] → 按目标索引预先扩大可见批次，再显式滚动到稳定 fragment。
- [Moment 专用视觉可能与博客割裂] → 复用字体、语义令牌、容器、控件、Footer、焦点与明暗模式，并进行桌面和移动回归。

## Migration Plan

1. 建立 Moment 内容模型、共享数据工具、配置与独立加载器，固定草稿、置顶、排序和 fragment 规则。
2. 基于 parser token 完成正文图库提取、四种富媒体复用和最终有序内容块模型；长文章输出保持不变。
3. 增加 `/moment` 路由、专用 Header、个人封面、滚动加载、深链、朋友圈时间、卡片、图库、照片预览和复制链接。
4. 以每种富媒体一个独立 Markdown 文件提供示例，普通图片统一复用现有 Live Photo poster，音乐继续使用原有网络来源。
5. 更新正式使用手册和测试，完成格式、样式、类型、单元、构建、浏览器与 OpenSpec 验收。
6. 回滚时移除导航与 `/moment` 页面即可恢复原公开界面；独立 `src/moments` 和配置不会改变现有 `/blog` 数据或路由。

## Open Questions

无阻塞问题。后续若增加新的 Moment 富媒体类型，应继续扩展同一可判别内容块联合类型和 token metadata 协议，不恢复 marker 或运行时 HTML 解析。
